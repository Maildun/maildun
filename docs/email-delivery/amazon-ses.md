# Amazon SES email delivery

Amazon SES is the **Recommended** provider for the first release. Maildun sends through the Amazon SES API and receives campaign delivery feedback from Amazon SNS.

Use Amazon SES when the workspace needs confirmed Delivery, Bounce, and Complaint statuses. Campaign open and click tracking is handled by Maildun for both SES and SMTP.

## What you need

- An Amazon SES verified sending identity.
- Production access if you need to send outside the SES sandbox.
- An IAM access key with the required SES send and configuration-set permissions.
- An SES configuration set.
- An SNS topic in the same AWS region as the SES connection.
- A public HTTPS Maildun installation so Amazon SNS can reach the webhook.

Create narrowly scoped IAM credentials for the same AWS account and region entered in Maildun.

## Set up Amazon SES

1. In Amazon SES, verify the email address or domain that Maildun will use as the sender.
2. Create a configuration set, for example `maildun-feedback`.
3. In Amazon SNS, create a topic in the same region as the configuration set.
4. Add an SNS event destination to the configuration set.
5. Enable **Delivery, Bounce, and Complaint** events only. Maildun provides its own campaign open and click tracking.
6. In Maildun, add an Amazon SES provider and enter the AWS region, IAM access key ID, IAM secret access key, configuration set, and SNS topic ARN.
7. Save the provider, then copy its **SNS webhook URL**.
8. Subscribe the SNS topic to that URL using the HTTPS protocol. Maildun validates the signed SNS message and confirms the subscription automatically.
9. Test delivery with explicit From and To addresses. A successful test verifies only this delivery connection.
10. Open **Settings → Sender**, add each exact From address, and complete its verification through this connection.

Maildun adds the configuration set and its own correlation tags to campaign messages. Do not omit the configuration set when recreating the SES event destination.

## How feedback changes a campaign delivery

| SES event                | Maildun result                                                                        |
| ------------------------ | ------------------------------------------------------------------------------------ |
| SMTP accepts the message | The delivery becomes `Sent`. This is not final delivery confirmation.                |
| Delivery                 | The latest matching attempt becomes `Delivered`.                                     |
| Transient bounce         | The matching non-terminal attempt becomes `Delayed`.                                 |
| Permanent bounce         | The matching attempt becomes `Bounced`, and a subscribed contact is unsubscribed.    |
| Complaint                | The matching attempt becomes `Complained`, and a subscribed contact is unsubscribed. |

Maildun stores each SNS event once, verifies the AWS signature, and accepts events only from the SNS topic configured for that connection.

## Changing providers

Every campaign send attempt keeps the provider and SES feedback configuration used for that attempt. If the workspace later replaces SES with SMTP, a late SNS event is still matched to the original attempt.

A late event from an older attempt does not overwrite the status of a newer attempt. A permanent bounce or complaint still unsubscribes the affected contact because continuing to send would harm sender reputation.

Open and click URLs are generated by Maildun, so engagement tracking continues after the provider changes.

## Current release scope

SES Delivery, Bounce, and Complaint feedback currently applies to campaign deliveries. Transactional and automation messages can use the workspace connection for sending, but they do not yet receive these provider feedback statuses.
